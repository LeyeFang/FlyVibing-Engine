# 测试需知

## 输入交互 (InputPipeline) ★

自 2025-07 起，所有 Editor 测试的鼠标/键盘交互统一使用 `InputPipeline`。
**禁止在 test 中直接注册 GLFW 回调** (`glfw.set_key_callback` 等)。

### 为什么

每个 test 原先手写 ~60 行 GLFW 回调样板（`on_key` / `on_mouse_button` / `on_cursor` /
`on_scroll` + 拖拽状态追踪 + 点击检测），逻辑重复且与主线 `EditorLayer.OnEvent`
行为不一致。

`InputPipeline` 将 GLFW 回调注册 + InputState 管理 + 拖拽/移动分流抽取为独立组件，
test 只需覆写业务钩子。

### 核心概念

```
GLFW 原始事件
  │
  ▼
InputPipeline (内部: 更新 InputState + 拖拽检测 + dx/dy 计算)
  │
  ▼
可覆写钩子 (test 只需设置关心的钩子):
  on_key(key, scancode, action, mods)
  on_mouse_button(button, action, mods, x, y)
  on_drag(button, dx, dy, x, y)      ← dx/dy 已算好
  on_move(x, y)                       ← 纯移动 (无按键)
  on_scroll(xoff, yoff)
```

### 主线摄像机约定

与 `EditorLayer.OnEvent` 一致：
- **中键拖拽** → 轨道旋转 (orbit)
- **中键+Shift 拖拽** → 平移注视点 (pan)
- **左键拖拽** → 不做任何事 (预留给 Gizmo/Pick)
- **滚轮** → 缩放 (zoom)

### 快速使用

```python
from Test._test_harness import TestHarness

def main():
    h = TestHarness("My Test")
    h.create_window()
    h.init_engine()
    renderer = h.create_renderer()
    cam = h.create_default_camera()   # 或 h.create_test_camera()

    # ★ 创建管线 + 加载主线摄像机预设
    pipeline = h.create_input_pipeline()
    pipeline.setup_editor_camera(cam)

    # 添加 test 专用按键
    pipeline.on_key = lambda k, sc, act, mods: (
        glfw.set_window_should_close(h.window, True)
        if act == glfw.PRESS and k == glfw.KEY_ESCAPE else None
    )

    # h.run_loop(cam)  — 主循环不变
```

### 钩子签名一览

| 钩子 | 签名 | 触发时机 |
|------|------|---------|
| `on_key` | `(key, scancode, action, mods)` | 键盘按下/释放/重复 |
| `on_mouse_button` | `(button, action, mods, x, y)` | 鼠标按键按下/释放 |
| `on_drag` | `(button, dx, dy, x, y)` | 按住鼠标时移动 (dx/dy 已算好) |
| `on_move` | `(x, y)` | 未按住鼠标时移动 |
| `on_scroll` | `(xoff, yoff)` | 滚轮 |

### 便利查询

```python
pipeline.is_dragging                # → bool
pipeline.drag_button                # → int | None (GLFW button code)
pipeline.press_pos                  # → (x, y)  按下时的位置
pipeline.click_detected(x, y)       # → bool     是否点击 (位移 < 4px)
pipeline.input_state                # → InputState  修饰键/按键状态
```

### 常用模式

**拾取 (左键单击 → pick_at)**：
```python
def on_mouse_button(button, action, mods, x, y):
    if button != glfw.MOUSE_BUTTON_LEFT: return
    if action != glfw.RELEASE: return
    if not pipeline.click_detected(x, y): return  # 拖拽过滤
    pick_type, pick_value = renderer.pick_at(x, y)
    # 处理拾取结果 ...

pipeline.on_mouse_button = on_mouse_button
```

**包裹主线预设的 on_drag (混合 gizmo 拖拽 + 摄像机)**：
```python
pipeline.setup_editor_camera(cam)
_orig_drag = pipeline.on_drag

def on_drag(button, dx, dy, x, y):
    if button == glfw.MOUSE_BUTTON_LEFT and gizmo_mode:
        # gizmo 拖拽逻辑 ...
    else:
        _orig_drag(button, dx, dy, x, y)  # 回退到主线预设

pipeline.on_drag = on_drag
```

**每帧更新拾取鼠标位置**：
```python
pipeline.on_move = lambda x, y: renderer.update_pick_mouse(x, y)
```

## 渲染命令 (RenderCommand) 模式 ★

所有 GPU 资源操作必须通过 `renderer.enqueue(Command(...))` 提交，**不得直接调用** `register_entity` / `register_overlay_drawable` 等方法。

### 原则
- **Command 封装 GPU 操作** — 调用方不知道渲染器具体实现
- **主线程 enqueue，渲染线程 execute** — 线程安全
- **`StartFrame` 消费命令队列后渲染** — 顺序保证

### 可用命令

| 命令 | 用途 |
|------|------|
| `EntityRegistrationCommand(eid, register=True/False)` | 实体 GPU 资源注册/解注册 |
| `OverlayRegistrationCommand(overlay_data)` | Overlay 可绘制对象注册 |
| `OverlayUnregistrationCommand(key)` | Overlay 可绘制对象解注册 |
| `ResizeCommand(w, h)` | 窗口尺寸变更（GLFW 回调中直接发送） |

### 示例

```python
from Application.Core.Renderer.RenderCommand import (
    EntityRegistrationCommand,
    OverlayRegistrationCommand,
)

# 实体注册 — 走 Command
renderer.enqueue(EntityRegistrationCommand(entity_id, register=True))

# Overlay 注册 — Grid/ViewGizmo/TransformGizmo 内部已走 Command
# 调用方只需调用 .register_to(renderer)，无需关心
Grid.register_to(renderer)         # 内部已使用 OverlayRegistrationCommand
ViewGizmo.register_to(renderer)    # 同上
TransformGizmo.register_to(renderer)  # 同上
```

## 数学注意事项 ★ (2026-07-07)

### pyrr 矩阵是 row-vector 约定

`calculate_entity_model()` 返回 pyrr `Matrix44`，采用 **row-vector** 约定：
- 位移存在最后 **一行**（不是最后一列）
- `v_world = v_local @ model` ✅
- `v_world = model @ v_local` ❌（位移被忽略，所有顶点挤压到原点）

```python
# 正确: 行向量 × 矩阵
p4 = np.append(local_point, 1.0)
world_point = p4 @ model          # model 是 pyrr Matrix44

# 错误: 矩阵 × 列向量 (位移在最后一列，但 pyrr 在最后一行)
world_point = model @ p4          # 永远返回模型空间原点!
```

### 方向 vs 位置 (w 分量)

用齐次坐标变换时注意 w 分量：

```python
# 方向向量 — w=0，跳過位移，仅应用旋转
dir_local = np.array([0, 0, -1, 0])  # 摄像机 local forward
dir_world = (dir_local @ model)[:3]

# 位置向量 — w=1，应用完整 TRS (旋转+位移)
pos_local = np.array([0, 0, 0, 1])   # 摄像机 local 原点
pos_world = (pos_local @ model)[:3]
```

### pyrr from_eulers 的参数顺序

`pyrr.Matrix44.from_eulers(Vector3([a, b, c]))` 按 **Z(a) → Y(b) → X(c)** 顺序解读：

```python
from_eulers([a, b, c])  =  Rz(a) @ Ry(b) @ Rx(c)
                          ↑ Z旋转   ↑ Y旋转   ↑ X旋转
```

`calculate_entity_model(position, rotation, scale)` 传入 `rotation = (rx, ry, rz)`，
内部调用 `from_eulers([rx, ry, rz])`，因此：

| 参数 | pyrr 解读为 | 含义 |
|------|------------|------|
| `rx` | Z 旋转 | roll (绕 forward) |
| `ry` | Y 旋转 | yaw (水平) |
| `rz` | X 旋转 | pitch (垂直) ← **注意: 不是 rx!** |

```
误区: 直觉认为 rx=pitch, ry=yaw, rz=roll
实际: pyrr 按 ZYX 解读 → rx=roll, ry=yaw, rz=pitch
```

### 编辑器坐标系 → GL 轴 → pyrr 参数 映射 ★

编辑器与 GL 坐标系不同，经过转换后 pyrr 参数的实际 GL 轴效果如下：

```
编辑器坐标:  X = GL +X (右),  Y = GL -Z (前),  Z = GL +Y (上)

pyrr from_eulers([rx, ry, rz]) 中:
  rx → GL-X 轴旋转 → 编辑器 X 轴 (pitch, 俯仰)
  ry → GL-Z 轴旋转 → 编辑器 -Y 轴 (roll, 绕视线滚转, forward 不变!)
  rz → GL-Y 轴旋转 → 编辑器 Z 轴 (yaw, 水平转向)
```

> **关键**: 摄像机 `local_forward = (0,0,-1)` 沿 GL -Z（= 编辑器 +Y 前）。  
> pyrr 参数 `ry` 绕 GL-Z 旋转 → 绕 forward 自身 → **roll，不影响朝向**。  
> 真正控制摄像机看向哪里的是 `rz`（yaw）和 `rx`（pitch）。

**实用建议**: 设置摄像机 entity 朝向时，先用穷举搜索（brute-force scan）确定正确的 euler 角度，不要手动推导。参见 `Test/pyrr_behavior_test.py`。

### pyrr 透视投影函数: fov 是角度制 ★

两个函数签名相同，**fov 参数都是角度制（degrees）**，不是弧度制：

```python
pyrr.matrix44.create_perspective_projection(fovy, aspect, near, far)
pyrr.matrix44.create_perspective_projection_matrix(fovy, aspect, near, far)
```

两个函数完全等价（p1 == p2），`fovy` 均以**度**为单位。

```python
# ✅ 正确: 直接传角度
proj = pyrr.matrix44.create_perspective_projection(45.0, 16/9, 0.1, 1000.0)

# ❌ 错误: 误以为需要弧度 → FOV 变成 0.785°，画面全白/全空
proj = pyrr.matrix44.create_perspective_projection_matrix(math.radians(45.0), ...)
```

> **教训**: 不要被 `_matrix` 后缀误导 —— 它和 `create_perspective_projection` 完全一样。pyrr 中所有角度参数（euler、fov）统一使用角度制。

### pyrr 对象与 numpy 不兼容

pyrr `Matrix44` / `Vector3` 对象参与 `numpy.linalg.norm()` 等运算会报错：
```
ValueError: cannot reshape array of size 3 into shape (4,4)
```

必须先转为 numpy：
```python
m = np.asarray(pyrr_matrix)           # 转为 numpy ndarray
v = np.asarray(pyrr_vector).flatten()  # 转为一维数组
```

### 编辑器 Gizmo 可视化尺寸

Camera frustum 等 gizmo 应使用**固定的小型可视化尺寸**，而非真实的摄像机参数：
- ❌ `far_plane = 1000` → 椎体棱线 1000 单位长，不可见
- ✅ `VIS_DEPTH = 1.5` → 固定 1.5 单位深，仅反映 FOV/aspect 的形状比例

### 编辑器坐标系

| 编辑器轴 | GL 轴 | 说明 |
|---------|-------|------|
| X | +X | 右 |
| Y | -Z | 前 |
| Z | +Y | 上 |

2D 模式的"地面"是 GL XZ 平面 (= 编辑器 XY 平面)。Camera 的 `local_forward` 默认 `(0,0,-1)` 指向前方 (GL -Z = 编辑器 +Y)。

## 摄像机轨道 (Orbit)

```python
def orbit(self, dx, dy):
    self.yaw += dx * 0.005    # X 拖拽 → ViewGizmo 立方体旋转方向与主线一致
    self.pitch += dy * 0.005
    self.pitch = max(-math.pi/2+0.01, min(math.pi/2-0.01, self.pitch))
```

**注意**: `yaw` 的符号影响 ViewGizmo 旋转方向，必须与主线 `EditorCamera.orbit` 一致。

## UI 面板测试 (ControllerRegistry + Mock 注入)

### 两种 UI 测试

| 类型 | 文件示例 | 运行方式 | 用途 |
|------|---------|---------|------|
| **纯 Python 交互测试** | `test_scene_panel_interactions.py` | 直接 `python` 运行，无 GUI | 验证 Controller 逻辑、Registry 行为、Mock 注入 |
| **Live UI 测试** | `test_live_ui.py` | 需要显示器 + GPU | 实时预览主线 Panel 的视觉改动 |

### 核心概念：Panel → Registry → Controller

```
Panel.__init__()
    └── get_ctrl("Simulation")  →  返回注册表中的 Controller 类
                                       │
                    ┌──────────────────┴──────────────────┐
                    ↓                                      ↓
              真 Controller                             Mock Controller
         (import 时 auto-register)                (测试手动 register 覆盖)
             真正启动引擎                            只记录调用、返回预设数据
```

**生产环境**：Controller 模块在 import 时自动调用 `register()` 注册自身。`EditorLayer` 确保 Controller 先于 Panel 导入。

**测试环境**：测试代码在创建 Panel 前手动 `register(name, MockClass)` 覆盖注册表。测试结束后调用 `ControllerRegistry.reset()` 清空。

### 纯 Python 交互测试模板

适用于 Controller 状态机、Registry 行为、Mock 注入验证：

```python
import sys, os
# ... _path_setup 引导 ...

from Application.Editor.Services.ControllerRegistry import (
    register, get_ctrl, reset,
    NAME_SIMULATION,
)
from Test.Helpers.MockControllers import MockSimulationController

def test_my_feature():
    # 1. 清理上一次测试的状态
    reset()
    MockSimulationController.reset()

    # 2. 注入 Mock（覆盖真 Controller）
    register(NAME_SIMULATION, MockSimulationController)

    # 3. 执行被测逻辑
    ctrl = get_ctrl(NAME_SIMULATION)
    ctrl.play()

    # 4. 验证
    assert ctrl.is_running(), "play() 后应进入 RUNNING 状态"
    assert MockSimulationController.play_called == 1, "play() 应被调用 1 次"

    # 5. 清理
    reset()
```

### Mock Controller 提供的能力

所有 Mock 类位于 `Test/Helpers/MockControllers.py`：

| Mock 类 | 关键验证字段 |
|---------|-------------|
| `MockSimulationController` | `play_called`, `pause_called`, `stop_called` (int 计数) |
| `MockSceneBrowserController` | `select_called_with` (list, 记录每次 select 的参数) |
| `MockResourceBrowserController` | `set_meshes()` / `set_shaders()` 等预设数据方法 |
| `MockViewportController` | `switch_to_2d_called`, `switch_to_3d_called` (int 计数) |

每个 Mock 都提供 `reset()` 类方法，在每个测试开始前调用以清零状态。

### Live UI 测试引导要点

`test_live_ui.py` 的关键初始化顺序（顺序错误会崩溃）：

```python
# 1. GLFW 窗口
# 2. 引擎最小引导 (ResourceManager.Init + SceneManager.Init)
# 3. ★ 先导入 Controller（触发 auto-register）
from Application.Editor.UI.controllers.SimulationController import SimulationController
from Application.Editor.UI.controllers.SceneBrowserController import SceneBrowserController
# ... 其余 Controller ...

# 4. ★ 再导入 Panel（Panel.__init__ 从 Registry 取 Controller）
from Application.Editor.UI.panels import ScenePanel, NodeEditorPanel

# 5. 注册 Panel 到 UIManager
UIManager.register(ScenePanel())
UIManager.register(NodeEditorPanel())

# 6. 主循环中调用 UIManager.draw_all()
```

> **为什么必须按这个顺序？**  
> `ScenePanel.__init__` 中调用 `get_ctrl(NAME_SIMULATION)` 从 Registry 获取 Controller。  
> 如果此时 Controller 还没 import（即还没 `register`），`get_ctrl` 返回 `None`，后续调用立即崩溃。

### 新建 Panel 时的检查清单

## ViewGizmo 旋转方向约定 ★

### 核心规则

`Core.Math.ViewGizmo.compute_cube_model()` 内部已通过 `SIGN_YAW = -1.0` 处理了 yaw 符号。
**调用方直接传入 `EditorCamera.yaw` 原值即可，严禁对 yaw 做任何额外取反。**

### 正确做法

```python
# ✅ 正确: yaw 原值传入
from Application.Core.Math.ViewGizmo import compute_cube_model
cam = EditorCamera.get_instance()
model = compute_cube_model(vp_w, vp_h, cam.yaw, cam.pitch)
```

```python
# ❌ 错误: 对 yaw 取反会导致旋转方向与主线相反
model = compute_cube_model(vp_w, vp_h, -cam.yaw, cam.pitch)
```

### 鼠标拖拽 → 旋转方向

| 鼠标拖拽 | yaw 变化 | ViewGizmo 立方体旋转 |
|----------|----------|---------------------|
| X 正方向 (右) | yaw 增大 | 绕 GL Y 轴（编辑器 Z 轴）逆时针 |
| X 负方向 (左) | yaw 减小 | 绕 GL Y 轴（编辑器 Z 轴）顺时针 |

### 测试中使用

所有测试通过 `setup_default_scene(renderer, with_gizmo=True)` 注册 ViewGizmo，
`register_view_gizmo()` 内部不施加任何 yaw 变换，直接委托主线 `ViewGizmo.register_to()`。
后续新增任何涉及 ViewGizmo 的测试都遵循此约定。
